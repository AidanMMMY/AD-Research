  1. 多端是「小体积、高税率」的拖累：代码量只占 7.3%，却占近 30 天代码改动的 22.3%、改密单一特性插入行的 27.6%、8/3–8/6 冲刺 commit 的 33.3%。拖累不在体积，在「每个横切特性 ×3 端复制 + 修竞态」的乘数效应。
  2. 旧 ios/ADResearch 应立即归档（退役第一候选）：全生命周期仅 3 个 commit，其中 2 个（66.7%）是 10-25 被后端改密倒逼的兼容补丁；目录内连 .xcodeproj 都没有（无法构建发布）；native 自己的 README:158-160 已写明「如确认废弃可另行删除」；全仓无任何 CI/脚本/编排引用。
  3. 瘦身报告全部结论今天仍成立（第四节逐条复核），包括旧 iOS refresh 轮换缺陷（AuthManager.swift:81 只回写 access、不存轮换后的 refresh，问题仍在）。
  4. research/ 五进程原型确认为死代码：orchestrator.py:46 丢弃 _interval、:84 每 300 秒复活已退出 agent；7-16 后零功能 commit；主平台/Dockerfile/compose 零引用。
  5. 核心后台不可砍论据扎实：生产 7 容器、scheduler 92 处 add_job、app 129K 行 + 124 个测试文件。
  6. 最划算的一刀：归档 ios/ + AGENTS.md 写死「Swift 客户端只保留一套」，预计消除每次横切特性约 10–15% 客户端税。

四、分级处置建议

4.1 四级总表

4.2 ios/ADResearch —— 退役（第一优先）

  • 工作量证据：全周期 3 commit / 1,195 插入行；2 commit（10-25）+ 476 行（占生命周期插入 39.9%）纯为改密兼容；119 天沉默；无 xcodeproj，无法构建也就不可能发布过。
  • 迁移成本：≈0。后端兼容 shim 已随 ee22869 上线；全仓 grep 无 CI/脚本/编排引用 ios/ADResearch。
  • 风险：仅剩「所有者私藏使用」可能，而目录无工程文件无法构建，可能性极低；动手前口头确认一次。
  • 回滚要点：单独 commit 执行 git rm -r ios/（历史永在）；回滚 = git checkout 0bcd07f -- ios/。同步删 AGENTS.md 目录段对应行，避免 AI 会话继续被误导。

4.3 native/ADResearch（macOS）—— 收窄为 companion

  • 工作量证据：17 commit / +14,274 行集中 8/3–8/5；之后 80 天零有机投入；改密特性付出 494 行（385 兼容 + 109 竞态修复）。
  • 保留理由：菜单栏行情、⌘K、深链、本地提醒是 Web 给不了的桌面效率；有 DMG 构建记录。
  • 收窄动作：功能冻结在晨读/资讯/宏观/标的/评分阅读路径；不再追 Web parity；下一步投入前先做真实 xcodebuild + 登录/refresh/研报解码三契约冒烟（手工 Codable 已两次漂移：b9d43d2、0bcd07f）。
  • 决策门：未来 60 天仍无有机 commit，则降级 Web-only 并归档。
  • 回滚要点：归档前打 tag（如 native-0.4.0-final）；深链 alloyresearch:// 若被外部笔记引用需先盘点。

4.4 native/ 内 iOS target —— 归档（实验冻结）

共享 target 无真机、无 TestFlight、无发布证据。冻结 = 不再为 iOS 形态单独适配（macOS 优先），成本几乎为零。

4.5 research/ —— 归档

  • 证据：9 文件 557 行；最后功能 commit 421130c（7-16），其后仅 ruff 顺手清理；orchestrator 缺陷（:46/:84）从未修；主平台零引用。
  • 迁移成本：≈0（价值已由 agent/overnight_research_v2 取代）。
  • 风险/回滚：无消费者；回滚 = git 历史。建议与 ios/ 分开各自单独 commit 归档。

4.6 agent/ —— 收窄（按源合并，不可一刀切停）

  • 证据：12 commit / 11,272 行，7–8 月有真实生产事故修复（TLS 指纹轮换、镜像丢失双保险）；生产 cron 每小时在跑。
  • 合并清单：CLS（与 news_cls_5m 同 endpoint，agent 侧停此源）、reddit、xueqiu 归主平台；保留 stocktwits（TLS 指纹抗 WAF）、x、fed_intl、gov_china、eastmoney_news 等独有源。

五、方法论与局限

  1. token 消耗为代理估算：无法读取 AI 会话原始 token 计量，用 git churn（代码产出）、dev-notes 字节（文档产出）、记忆库条目占比（主题分布）三类代理。真实 token 含读代码/排障等未落盘部分，代理低估会话次数，但方向与占比稳健。
  2. commit 归属：横切 commit 在分目录统计中重复计数，各目录 commit 之和 > 总数；行数按 numstat 聚合无重复。
  3. 近 30 天仅 14 commit，小样本放大改密特性占比；因此同时给出全窗口（530 commit）数据：native+ios 仅占 churn 3.2%——结论不是「多端吃掉大盘」，而是「横切特性税率极高且无对等用户价值」。
  4. 「无使用」基于无遥测推断：仓内证据（无 CI、无发布、沉默期、无 xcodeproj）强烈但非绝对；退役前做一次所有者确认。
  5. 生产运行态引用昨日瘦身报告的 ECS 只读核验（docker ps + cron），本日未重复登录生产。
